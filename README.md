# نظام متابعة الجودة (QC Tracking)

تطبيق ويب **متعدد المستخدمين** لمتابعة جودة الإنتاج، يعمل بـ **Firebase (Auth + Firestore)** كقاعدة بيانات سحابية، ومصمّم كـ **PWA** (يُثبَّت على الجوال ويعمل جزئياً بدون إنترنت).

## المزايا
- **حسابات ومساحات عمل:** كل شركة/قسم = مساحة عمل، يشترك فيها عدة مفتشين بكود دعوة.
- **المصانع والموردون:** إدارة قائمة المصانع.
- **الطلبيات:** ربط كل طلبية بمصنع + الكمية + الموديل.
- **الفحوصات:** تسجيل الفحص (عينة، عيوب كبيرة/صغيرة/حرجة) مع **حساب DHU وقرار AQL تلقائياً** (مقبول/مرفوض).
- **لوحة مؤشرات حيّة:** عدد الفحوصات، متوسط DHU، نسبة الاجتياز (RFT)، رسم بياني.
- **أدوات:** حاسبة النقاط الأربع، حاسبة الانكماش، جدول AQL التفاعلي.

## بنية البيانات (Firestore)
مجموعات مستقلة بادئتها `qc_` لا تمسّ بياناتك الحالية:
`qc_members` · `qc_workspaces` · `qc_factories` · `qc_orders` · `qc_inspections` · `qc_defects` · `qc_models` · `qc_seqcfg` · `qc_chkcfg` · `qc_toolchecks`

## خطوات التشغيل (مرة واحدة)
1. **نشر قواعد الأمان:** في Firebase Console (**Firestore → Rules**) لمشروع `level7alaa`:
   - إن كان المشروع لنظام الجودة فقط: الصق كامل ملف **`firestore-full.rules`** (بديل كامل).
   - أو إن كانت لديك قواعد أخرى: ادمج كتل **`firestore-qc.rules`** داخل بلوك `match /databases/{database}/documents { … }` الحالي بجانب قواعدك.
   ثم **Publish**. بدون هذه الخطوة ستظهر رسالة «صلاحيات غير مفعّلة». **بعد أي تعديل على القواعد شغّل `npm test` ثم أعد النشر.**
2. **تفعيل تسجيل الدخول بالبريد:** Firebase Console → Authentication → Sign-in method → **Email/Password → Enable** (غالباً مفعّل مسبقاً).
3. **الاستضافة:** فعّل GitHub Pages للمستودع، وسيكون التطبيق على مسار `/qc/`. أضف نطاق `github.io` في Firebase → Authentication → **Authorized domains** إن لزم.

## الاستخدام
1. أنشئ حساباً (البريد + كلمة المرور + الاسم).
2. **أنشئ مساحة عمل** (تحصل على كود مثل `QC-4821`) أو **انضم بكود** زميلك.
3. أضف المصانع ← الطلبيات ← ابدأ تسجيل الفحوصات.

## الاختبارات (للمطوّر)
- `npm run audit` — تدقيق ثابت لملف `index.html` (صياغة JS، مفاتيح الترجمة المفقودة/المكرّرة/تطابق ع‑إ، المعالِجات غير المعرّفة).
- `npm run test:rules` — يشغّل محاكي Firestore ويختبر قواعد الأمان (`firestore-full.rules`) عبر `tests/rules.test.mjs` — يتطلّب Java و`npm install` أولاً.
- `npm test` — يشغّل الاثنين معاً. **شغّله بعد أي تعديل على القواعد** قبل النشر.

يعمل هذان الفحصان تلقائياً على كل دفع عبر GitHub Actions (`.github/workflows/ci.yml`).
